# pgb-docs — docs infra

Standalone infrastructure repo for the **pgb documentation site**: an
open-source [Starlight](https://starlight.astro.build) (Astro) site with
[Keystatic](https://keystatic.com) as a git-based CMS, running entirely
locally under Docker Compose. $0, no vendor services.

Replaces the Mintlify setup (`~/data/pgb/docs`, port 3736).

## Run it

```bash
cd ~/data/pgb-docs
docker compose up --build
```

| URL | What |
| --- | --- |
| <http://localhost:3737> | the docs site |
| <http://localhost:3737/keystatic> | CMS admin UI (dev server only) |

First start builds the image and installs deps into a named Docker volume
(`docs_node_modules`) — the repo tree on the host stays clean. Subsequent
starts are fast.

Stop: `Ctrl-C` (foreground) or `docker compose down`. The volume survives;
reset deps with `docker compose down -v`.

## Where docs live

One file = one page. The file path **is** the URL.

```
src/content/docs/
├── index.mdx            ← landing page (splash hero) — hand-edit only
└── guides/
    ├── quickstart.mdx    ← http://localhost:3737/guides/quickstart
    └── authoring.mdx     ← this guide, as a page
```

- **Guides** (and any other configured section) appear in the sidebar
  automatically — just create `guides/my-page.mdx`.
- **New section** = new directory under `src/content/docs/` **plus** a
  `sidebar` entry in `astro.config.mjs`:

  ```js
  sidebar: [
    { label: 'Guides', autogenerate: { directory: 'guides' } },
    { label: 'Reference', autogenerate: { directory: 'reference' } },
  ]
  ```

## How to save a doc

### Way 1 — browser (Keystatic)

1. Open <http://localhost:3737/keystatic>
2. Pick **Docs** (top-level pages) or **Guides**
3. Edit, hit **Save**

Save writes the `.mdx` file straight into `src/content/docs/` and the site
hot-reloads. **Saving is not versioning** — Keystatic local mode never
touches git. Versioning is this repo:

```bash
cd ~/data/pgb-docs
git add -A && git commit -m "docs: ..."   # your save point
git push                                   # once a remote exists
```

### Way 2 — editor

Edit files directly under `src/content/docs/` — same hot reload, full
control (required for the landing page and any Starlight-specific
frontmatter).

### Frontmatter contract

```yaml
---
title: My page        # required — becomes the slug of NEW pages
description: One line # subtitle + search/meta
sidebar:
  order: 2            # optional — position inside an autogenerated section
---
```

> **Gotcha:** Keystatic drops frontmatter keys it doesn't know when saving
> through the UI. `title`/`description` are safe; pages using Starlight
> extras (`template`, `hero`, `sidebar`, `prev`/`next`) are hand-edit-only
> (`index.mdx` is one). To make such a key survive Keystatic saves, declare
> it with `fields.ignored(...)` in `keystatic.config.ts`.

## Search

Built-in [Pagefind](https://pagefind.app/) — a static, self-hosted index,
no cloud service. In dev, Starlight serves a live dev search; production
index rebuilds on every `npm run build`.

## Production build

Keystatic is wired **dev-only** (`astro.config.mjs` adds it when
`command === 'dev'`), so the production build is a pure static export with
no adapter or server needed:

```bash
docker compose exec docs npm run build   # → dist/
```

Deploy `dist/` anywhere static (GitHub Pages, Cloudflare Pages). Remember
to set `site` + `base` in `astro.config.mjs` to the deploy URL first.

## Repo layout

```
├── astro.config.mjs        # Starlight config: title, sidebar, theme
├── keystatic.config.ts     # CMS collections ↔ src/content/docs paths
├── src/
│   ├── content.config.ts   # Astro content collection (Starlight loader)
│   ├── content/docs/       # THE DOCS (all versioned content lives here)
│   └── custom.css          # indigo palette + Space Grotesk
├── Dockerfile              # node:24-alpine + su-exec (uid 1000 file perms)
├── docker-entrypoint.sh    # npm install → drop to node user → astro dev
└── docker-compose.yml      # port 3737, bind mount, deps volume
```

## Known trade-offs

- **Versioning** is not native in Starlight. When needed, add the
  community plugin [`starlight-versions`](https://github.com/HiDeoo/starlight-versions)
  (actively maintained, but early-stage — pin the version).
- **Keystatic's editor** is prose-grade: code blocks/headings/lists edit
  fine; Starlight JSX components inside pages (`<Tabs>`, `<Cards>`,
  `<Aside>`) are not first-class in the UI — edit those in an editor.
- **Remote editing** (Keystatic GitHub mode, i.e. the CMS reachable on a
  public URL committing to GitHub) requires switching Astro to
  `output: 'hybrid'` + an adapter + a GitHub App. Deliberately not set up
  here — local-first.

## Migrating the old Mintlify content

The 38 Mintlify MDX pages still live in `~/data/pgb/docs` (served on :3736
until retired). Porting is mechanical: `Note` → `:::note`,
`CodeGroup` → Starlight `<Tabs>`/code fences, `CardGroup`/`Card` → native
`Cards`/`Card`, `Accordion` → `<details>`, then rewrite internal links
(`/welcome/quickstart` → `/guides/quickstart`, ...).
